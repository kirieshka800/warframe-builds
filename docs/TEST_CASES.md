# Тест-кейсы Tenno Lab

Дата: 18 ноября 2026. Основание: исходники [72d4643](https://github.com/kirieshka800/warframe-builds/tree/72d4643c5592de88b21208be1b0e33ccc7254fb0).

**126 тест-кейсов, 25 функциональных областей.** Это спецификация проверок, а не протокол успешного выполнения. Все строки [TEST_RUN.csv](TEST_RUN.csv) изначально имеют статус `NOT_RUN`. В рамках этого изменения выполнена проверка документации и ссылок; все перечисленные ручные сценарии заново не прогонялись.

Описание возможностей: [FEATURES.md](FEATURES.md). Краткий маршрут проверки: [TESTING.md](TESTING.md). Исторические результаты автоматизации: [VERIFICATION.md](VERIFICATION.md).

## Подготовка

1. Развернуть **отдельные тестовые экземпляр сайта и PostgreSQL** по [README](../README.md). Проверки удаления, миграций, изменения каталога и отказов не проводить на рабочей базе.
2. Подготовить два независимых профиля A/B в разных контекстах браузера и гостя G. Для проверки одинаковых имён использовать одинаковые имена, но разные cookie.
3. В каталоге нужны Rhino, Braton, Lato, Skana, Bo; стандартные моды Vitality, Redirection, Flow, Corrosive Projection, Steel Charge, Serration, Iron Phoenix, Flailing Branch. Если записи отсутствуют, сначала загрузить каталог либо отметить соответствующую проверку `BLOCKED` с причиной.
4. Создавать записи с префиксом `QA-`; записывать их ID/URL. Для пагинации нужны минимум 13 билдов и 25 предметов; для 101 комментария использовать отдельную фикстуру. Не ожидать, что стартовая подборка уже заполняет все страницы.
5. Фиксировать базовые значения, описание эффекта выбранного ранга и MaxRank непосредственно из тестового каталога. Для математических кейсов с искусственными числами использовать отдельные фикстуры калькулятора, не подменять реальную БД.
6. Для сетевых/Steam/clipboard/миграционных случаев заранее подготовить соответствующее окружение. Недоступная зависимость — `BLOCKED`, а не `PASS`.

CSV сохранён в UTF-8 с BOM, разделитель — `;`. Если Excel открыл один столбец, используйте импорт «Из текста/CSV», выберите UTF-8 и точку с запятой. Многострочные шаги находятся в кавычках.

## Правила прогона

- `P0` — критичный пользовательский путь или защита данных; `P1` — основная/негативная функциональная проверка; `P2` — дополнительные условия интерфейса и устойчивости. Для быстрого смоук-прогона в первую очередь выполнять P0.
- Значения на границе длины создавать ASCII-символами, чтобы не смешивать число символов, UTF-16 и байты UTF-8. Размер JSON проверять именно в байтах.
- Если браузер не даёт ввести невалидное значение, серверную проверку выполнять HTTP-клиентом с **собственными действительными cookie и antiforgery**. В кейсах CSRF токен специально пропускается/портится.
- HTTP-отказ cookie-аутентификации может сначала перенаправлять на страницу ошибки/входа. Проверять итоговый результат, отсутствие изменения БД и статус после перехода; не считать любой 302 успешной операцией.
- Для кейса с несколькими наборами данных выполнить каждый набор отдельно; добавить копию строки в CSV и заполнить колонку «Вариант». Один успешный вариант не закрывает остальные.
- Заполнять `PASS / FAIL / BLOCKED / NOT_RUN`, фактический результат, дефект, исполнителя, дату, commit SHA. При FAIL сохранять шаг, URL и обезличенные логи; не прикладывать пароли, cookie и токены.
- Отдельные P0 проверки не заменяют полный регресс; корректный расчёт в планировщике не означает полную симуляцию игры.

**Ожидаемый результат:** Профиль создан, имя видно в шапке; собственный каталог доступен.

### TC-AUTH-02 — Пустое и пробельное имя

- **Функции:** F02. **Приоритет:** P1.

**Ожидаемый результат:** Сервер показывает ошибку длины/ввода; новая авторизованная сессия не создаётся.

### TC-AUTH-03 — Границы имени

- **Функции:** F02. **Приоритет:** P1.
- **Предусловия:** Каждый вариант — новый тестовый контекст; POST с действительным токеном.

**Шаги:**

1. Создать профиль с 1 символом.
2. Повторить с 50.
3. Повторить с 51.

**Ожидаемый результат:** Длины 1 и 50 принимаются; 51 отклоняется без создания профиля.

### TC-AUTH-04 — Одинаковые имена не дают общих прав

- **Функции:** F02, F04. **Приоритет:** P0.

**Ожидаемый результат:** B не получает владение записями A; публичное чтение доступно, редактирование/удаление — нет.

## Существующая автоматизация

| Проверка | Файл/команда | Область |
| --- | --- | --- |
| Расчёты | `dotnet run --project tests/CalculationChecks` | Формулы, полярности, ранги, условные эффекты |
| Планировщик и кеш | `dotnet run --project tests/AutoBuildChecks` | Цели, совместимость, бюджет, детерминированность и ограничение кеша |
| Основной HTTP | [http_checks.py](../tests/http_checks.py) | Профили, CSRF, владение, билд/JSON/комментарий/гайд |
| Автоподбор HTTP | [auto_build_http.py](../tests/auto_build_http.py) | Предпросмотр, подтверждение, отмена, повтор/гонка, изменение каталога |
| Основной браузер | [browser_checks.py](../tests/browser_checks.py) | Ручной конструктор, сохранение и адаптивность |
| Автоподбор браузер | [auto_build_browser.py](../tests/auto_build_browser.py) | Выбор цели, предпросмотр, отмена и подтверждение |

Это частичное автоматическое покрытие, а не отметка PASS для всех кейсов выше. Steam, управляемые сбои сети, размерные границы и миграционные фикстуры требуют своих проверок. Команды и зависимости описаны в README.

## Завершение

Удалить только созданные тестовые записи и восстановить изменённые фикстуры/конфигурацию/сетевой доступ. Для локального профиля сохранить необходимые JSON до выхода. Не удалять рабочие тома PostgreSQL и ключи подписи сессий ради очистки тестов.
