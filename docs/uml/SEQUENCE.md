# ЛР18. Диаграмма последовательности

[Draw.io](diagrams/05-sequence.drawio) · [Изображение](previews/05-sequence.svg) · [PDF](05-sequence.pdf)

Сценарий: удаление существующей сборки авторизованным пользователем. Диаграмма намеренно небольшая: одна страница 1280 × 840, четыре участника, 12 сообщений и один комбинированный фрагмент `alt`.

Участники: пользователь, интерфейс в браузере, экземпляр BuildsController и экземпляр ApplicationDbContext. Последний обозначает объект доступа к PostgreSQL, а не отдельный сервер с таким именем.

Сначала контроллер получает сборку через FindAsync и проверяет Owns(build). В ветви владельца он помечает сборку на удаление и сохраняет изменения. Затем возвращает перенаправление к собственным сборкам. В другой ветви отвечает 403 без удаления.

Сплошные стрелки — вызовы, пунктирные — ответы. Вертикальные пунктиры — линии жизни, узкие прямоугольники — периоды выполнения. Время направлено сверху вниз.

Для компактности показаны два результата одного сценария. Предусловия: вход выполнен, сборка существует, диалог удаления подтверждён, CSRF-проверка пройдена. SaveChangesAsync вызывается внутри вспомогательного Save(). Последующий GET после HTTP 302 свёрнут в отображение списка сборок с сообщением. В успешной ветви предполагается успешное сохранение в БД.

Основание: [BuildsController.cs](https://github.com/kirieshka800/warframe-builds/blob/00ab52aefc9a5348f64f5e2b18e5b9f9b74fe3d9/WarframeBuilds/Controllers/BuildsController.cs), методы Delete, Owns и Save.
