# ЛР30. Приоритетные чек-листы Warframe Builds

**15 проверок в пяти чек-листах.** Выбраны интересные и важные сценарии: автоматический подбор, вместимость, расчёт характеристик, обмен сборками и защита данных. Полное покрытие всех функций проекта здесь не заявляется.

Дата составления: 24.11.2026. Основание: исходники `afadfc94810e30aa21783787e6aee212b4b16d46`.

Это документ для ручного прогона, а не отчёт об успешном тестировании. Исходный статус каждой проверки — **НЕ ВЫПОЛНЕНО**.

## Подготовка

1. Запустить отдельный тестовый экземпляр сайта и PostgreSQL по [README](../README.md). Для каждого расчётного сценария создавать свежую сборку: моды из соседних проверок не переносить.
2. Использовать встроенный стартовый каталог без синхронизации WFCD. Если каталог уже обновлён, числовые проверки проводить на чистой тестовой БД либо сначала зафиксировать фактические базовые значения: нельзя считать изменение каталога ошибкой калькулятора.
3. Подготовить профили А и Б в независимых контекстах браузера и гостевое окно G. Для серверных проверок использовать DevTools / HTTP-клиент; запросы отправлять с cookies и CSRF-токеном соответствующего профиля, изменяя только проверяемые поля.
4. Нумерация слотов в запросах: 0–7 — обычные; 8 — аура/стойка, если она доступна этому типу снаряжения; 9 — эксилус. При открытии чужого билда подставлять реальный ID, а не текст `{ID_A}`.

## Заполнение результатов

Статусы: **НЕ ВЫПОЛНЕНО**, **ПРОЙДЕНО**, **НЕ ПРОЙДЕНО**, **ЗАБЛОКИРОВАНО**. Рядом со статусом записывать фактический результат и ссылку на дефект, если он найден. Если перечислено несколько вариантов, отмечать результат каждого; общая проверка пройдена только после успеха всех вариантов. Состояние «заблокировано» означает, что выполнить проверку помешала неподготовленная среда или данные.

Для отметок в таблице: [CHECKLIST_RUN.csv](CHECKLIST_RUN.csv). Для Word: [CHECKLISTS.docx](CHECKLISTS.docx). CSV использует UTF-8 с BOM и разделитель `;`.
